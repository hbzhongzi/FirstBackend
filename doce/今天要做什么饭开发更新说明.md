# “今天要做什么饭”开发更新说明

## 1. 更新背景

根据 `api/sample/今天要做什么饭-示例.html` 原型和接口落地说明，本次将“今天要做什么饭”从浏览器本地演示状态拆分为可服务端持久化的业务模块。

原型中的 `localStorage`、内存数组和随机数只用于演示，不能作为正式用户数据来源。正式版本需要以当前小程序的 `program_id` 和登录用户的 `user_id` 为边界保存数据。

| `api/sample/今天要做什么饭-后端接口落地说明.md` | 接口、业务规则、数据隔离和验收基线 |

前端接入以[前端接口文档](../api/sample/今天要做什么饭-前端接口文档.md)为准，原型中的 `localStorage` 仅保留为界面演示，不再作为正式数据来源。

## 3. 模块拆分

### 3.1 美食内容模块

负责美食名称、Emoji、简介、起源、家常步骤和科普贴士。平台或小程序管理员维护，用户只能读取启用内容。

建议代码目录：

```text
app/mini/{programKey}/controller/v1/FoodController.php
app/mini/{programKey}/service/FoodService.php
app/mini/{programKey}/model/Food.php
app/mini/{programKey}/validate/FoodValidate.php
```

### 3.2 奖池模块

负责用户启用美食的读取和整体覆盖保存。新用户默认使用当前项目全部启用美食；已有用户不因读取接口重复全选。

建议接口：

```text
GET /api/{programKey}/v1/food-pool
PUT /api/{programKey}/v1/food-pool
```

### 3.3 抽取模块

转盘和盲盒共用 `POST /food-draws`。客户端只提交 `mode` 和幂等键，服务端读取奖池、生成随机结果、写入记录并更新图鉴。

```text
POST /api/{programKey}/v1/food-draws
GET  /api/{programKey}/v1/food-draws
```

抽取写操作必须使用事务和幂等键；动画不参与结果计算。

### 3.4 图鉴与统计模块

图鉴基于 `mini_food_book` 聚合，个人中心读取抽取总次数和收集数量。禁止客户端直接提交 `draw_count` 或 `book_count`。

```text
GET /api/{programKey}/v1/food-book
GET /api/{programKey}/v1/food-book/{food_id}
GET /api/{programKey}/v1/food-stats
```

### 3.5 反馈模块

支持 `feature`、`bug`、`food_recommendation`、`other` 四类反馈，默认状态为 `pending`，后台处理后更新状态。

```text
POST /api/{programKey}/v1/feedback
```

反馈内容需要长度校验、敏感内容检查、限流和幂等控制。

## 4. 开发实施顺序

1. 确认目标小程序已注册，取得 `program_id`。
2. 在开发库执行 `database/food_module.sql`，确认 12 项初始美食数据。
3. 将 SQL 表转换为正式 migration，补充项目使用的表前缀处理和回滚脚本。
4. 实现美食内容和奖池 Service，再实现抽取事务。
5. 实现图鉴聚合、个人统计和反馈提交。
6. 在 `route/mini_programs/{programKey}.php` 注册业务路由。
7. 前端移除以 `localStorage` 为事实来源的逻辑，改为接口初始化、服务端抽取和接口刷新。
8. 完成接口测试、隔离测试、幂等测试和并发测试后再接入真实小程序。

## 5. 事务与并发要求

抽取流程必须按照以下顺序执行：

```text
校验项目和用户
  → 校验幂等键
  → 读取当前有效奖池
  → 服务端随机选择美食
  → 写入 mini_food_draw
  → upsert mini_food_book
  → 提交事务并返回结果
```

重复幂等键直接返回第一次抽取结果，不重复增加抽取次数。奖池为空返回业务码 `42201`，频率超限返回 `42900`。

## 6. 测试更新要求

每个模块至少覆盖：

- 正常返回和字段类型校验。
- 未登录、无效 Token 和已停用小程序。
- 跨小程序和跨用户 ID 越权访问。
- 空奖池、停用美食和非法美食 ID。
- 抽取幂等、反馈幂等和并发重复提交。
- 图鉴次数与抽取明细的一致性。
- 反馈内容长度、敏感内容和频率限制。
- `request_id` 与项目日志的关联。

## 7. 联调命令

```bash
php think route:list
mysql -h127.0.0.1 -P3306 -u mytotal_app -p mytotal < database/food_module.sql
```

接口联调使用 `/api/{programKey}/v1` 版本化路径，并携带：

```text
Authorization: Bearer <access_token>
X-Request-Id: <request_id>
```

验收时应检查 `runtime/program_logs/{programKey}/YYYY-MM-DD.log` 是否有对应请求记录，日志不得包含 Token、密钥、完整请求体或用户敏感信息。
