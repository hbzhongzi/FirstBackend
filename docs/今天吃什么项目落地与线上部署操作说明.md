# “今天吃什么”项目落地与框架线上部署操作说明

> 本文用于把当前 ThinkPHP 8 多小程序后台模板部署为可联调、可上线的“今天要做什么饭”小程序服务。项目代码中的 programKey 为 sample，业务名称为“今天吃什么”。生产环境请将示例域名、账号、路径和密钥替换为实际值。

## 1. 适用范围

本文覆盖以下内容：

- 框架线上运行环境和 Web 入口配置；
- sample 小程序注册、微信登录密钥写入和数据初始化；
- Redis 缓存、图片固定目录、按小程序分区日志；
- 发布验收、日常升级、回滚和常见故障排查。

当前业务接口根路径为：

~~~
/api/sample/v1
~~~

接口明细、请求字段和响应示例见 [sample 前端接口文档](../api/sample/今天要做什么饭-前端接口文档.md)。数据库字段和 seed 说明见 [sample SQL 落地文档](../api/sample/今天要做什么饭-SQL落地文档.md)。

## 2. 部署架构与目录边界

~~~
微信小程序
    |
HTTPS 域名
    |
Nginx/Apache（站点根目录必须是 public/）
    |
ThinkPHP 入口 public/index.php
    |
公共中间件 -> sample 业务路由 -> Controller -> Service -> Model
    |                         |
 MySQL                     Redis
    |
public/storage/images/ 运行时图片
runtime/program_logs/  按小程序和日期分区的 JSON Lines 日志
~~~

必须遵守以下边界：

| 目录/组件 | 用途 | 线上要求 |
| --- | --- | --- |
| public/ | 唯一 Web 根目录 | 对外开放，其他项目目录不得作为站点根目录 |
| public/storage/images/ | 图片固定存储 | PHP 可写，Web 可读，禁止执行脚本 |
| runtime/ | 缓存、临时文件和日志 | 不允许通过 Web 访问 |
| runtime/program_logs/{programKey}/ | 小程序 API 日志 | PHP 可写，按日期轮转和清理 |
| database/migrations/ | 版本化表结构 | 已执行迁移禁止修改 |
| database/food_module.sql | “今天吃什么”初始内容 | 只导入目标 program_key，不要当作结构迁移 |

## 3. 上线前准备

### 3.1 服务器要求

- PHP 8.0+，建议 PHP 8.2；启用 pdo_mysql、openssl、mbstring、fileinfo。
- Composer 2。
- MySQL 5.7+，建议 MySQL 8.0，字符集使用 utf8mb4。
- Redis 3+。未启用 PHP ext-redis 时保留项目依赖的 predis/predis。
- Nginx + PHP-FPM 或 Apache + PHP。生产环境不使用 php think run。
- 微信小程序后台已配置合法业务域名、HTTPS 证书和请求域名。

检查版本和扩展：

~~~bash
php -v
php -m
composer --version
composer check-platform-reqs
~~~

### 3.2 获取代码

~~~bash
git clone https://github.com/hbzhongzi/FirstBackend.git mytotal
cd mytotal
git checkout main
git pull --ff-only
composer install --no-dev --optimize-autoloader
~~~

不要修改 vendor/，不要将 .env、数据库密码、Redis 密码、微信 AppSecret 或 Token 提交到仓库。

### 3.3 创建生产环境变量

当前项目从 .env 读取环境配置。生产服务器应由部署系统或密钥管理系统写入 .env，不能复制开发环境中的真实值。至少配置：

~~~dotenv
APP_DEBUG=false
APP_URL=https://api.example.com
APP_KEY=<稳定且随机的应用密钥>

DB_DRIVER=mysql
DB_TYPE=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=mytotal
DB_USER=mytotal_app
DB_PASS=<数据库密码>
DB_CHARSET=utf8mb4
DB_PREFIX=

CACHE_DRIVER=redis
CACHE_EXPIRE=0
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<Redis密码，可为空>
REDIS_DB=0
REDIS_TIMEOUT=2
REDIS_PERSISTENT=false
REDIS_PREFIX=mytotal:
~~~

APP_KEY 一旦用于加密小程序密钥、OpenID 或手机号，不能在没有数据迁移方案的情况下更换。修改 .env 后执行 php think clear。

## 4. 创建数据库并执行迁移

### 4.1 创建数据库和应用账号

使用具有建库/授权权限的管理员账号执行，密码请替换为随机强密码：

~~~sql
CREATE DATABASE mytotal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mytotal_app'@'127.0.0.1' IDENTIFIED BY '<数据库密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX
  ON mytotal.* TO 'mytotal_app'@'127.0.0.1';
FLUSH PRIVILEGES;
~~~

### 4.2 执行公共表和业务表迁移

~~~bash
php database/migrate.php status
php database/migrate.php up
~~~

确认输出包含以下迁移：

~~~text
202610300001_create_public_tables
202610300002_create_food_module
202610310001_add_program_secret_ciphertext
~~~

迁移器支持 status、up、down。MySQL 的建表/改表会隐式提交，迁移失败后不能假设事务已回滚；应先检查实际表结构和备份，再重试。生产环境禁止把 down 当作普通升级命令使用。

## 5. 注册“今天吃什么”小程序

### 5.1 写入项目注册记录

config/mini_programs.php 负责路由白名单，数据库 sys_mini_program 负责 AppID、启用状态和密钥密文，两者必须同时存在且状态一致。

~~~sql
INSERT INTO sys_mini_program
  (program_key, name, appid, status, created_at, updated_at)
VALUES
  ('sample', '今天吃什么', 'wx-your-appid', 1, NOW(), NOW());
~~~

不要在 SQL 或配置文件中写入 AppSecret 明文。新增其他小程序时，先在 config/mini_programs.php 增加白名单，再创建对应的 app/mini/{programKey}/ 和 route/mini_programs/{programKey}.php。

### 5.2 写入微信 AppSecret 密文

~~~bash
php database/set_mini_program_secret.php wx-your-appid your-app-secret
~~~

命令会读取 APP_KEY，加密后写入 sys_mini_program.secret_ciphertext。登录失败时：

- 50000：检查 APP_KEY 是否与写入密文时一致，并重新执行命令；
- 50300：检查 AppID、AppSecret、服务器出网能力和微信接口状态；
- 40401：检查 program_key、数据库注册记录和启用状态。

## 6. 导入“今天吃什么”初始内容

迁移只创建表，初始 12 项美食由 seed SQL 导入。确认 sample 已注册并启用后执行：

~~~bash
mysql -h127.0.0.1 -P3306 -u mytotal_app -p mytotal < database/food_module.sql
~~~

脚本通过 @program_key = 'sample' 查询 sys_mini_program，重复执行不会按名称重复插入。切换到其他小程序时，先在脚本中把 @program_key 改成目标值，并在预发库验证后再执行生产导入。

检查数据：

~~~sql
SELECT id, program_key, name, appid, status
FROM sys_mini_program
WHERE program_key = 'sample';

SELECT COUNT(*) AS food_count
FROM mini_food f
JOIN sys_mini_program p ON p.id = f.program_id
WHERE p.program_key = 'sample' AND f.status = 1;
~~~

首次调用 GET /food-pool 时，服务端会把当前小程序启用的美食初始化到当前用户奖池。

## 7. Redis、图片和日志配置

### 7.1 Redis

项目默认使用 Redis：

~~~bash
php think clear
redis-cli -h 127.0.0.1 -p 6379 ping
~~~

若 PHP 未启用 ext-redis，Composer 的 predis/predis 仍可提供客户端。若启用 ext-redis，确认 PHP 配置中是独立的一行 extension=php_redis.dll，不要出现 php_redis.dlltrack_errors=On 这类拼接内容。Redis 不可用时不要在线上静默切换到 file，应先恢复 Redis 或按变更流程处理。

### 7.2 图片目录和权限

Linux 示例：

~~~bash
mkdir -p runtime/program_logs public/storage/images
chown -R www-data:www-data runtime/program_logs public/storage/images
chmod -R u=rwX,g=rwX,o= runtime/program_logs
chmod -R u=rwX,g=rX,o= public/storage/images
~~~

Windows/PHPStudy：确认 Apache/PHP 运行账号对 runtime/program_logs 和 public/storage/images 有写权限。图片按以下规则保存：

~~~
public/storage/images/{programKey}/YYYY/MM/{随机文件名}.jpg
~~~

服务端只允许 JPEG、PNG、WebP，文件名由服务端生成。Web 服务器必须禁止 php、phtml、phar 等脚本在图片目录执行。

### 7.3 日志

API 日志位置：

~~~
runtime/program_logs/{programKey}/YYYY-MM-DD.log
~~~

排查接口时，先从响应头 X-Request-Id 或 JSON 的 request_id 定位对应日志。日志不应记录 Token、AppSecret、数据库密码、完整请求体或微信 session 信息；生产环境配置日志轮转、保留期限和磁盘空间告警。

## 8. Web 服务器上线配置

### 8.1 Apache/PHPStudy

站点根目录必须设置为：

~~~
D:\phpstudy_pro\WWW\Mytotal\public
~~~

启用 mod_rewrite，允许 .htaccess（AllowOverride All），修改后重启 Apache。项目 public/.htaccess 已包含 ThinkPHP 重写和 Authorization 请求头转发。若小程序请求头中有 Bearer，但 PHP 返回 40100/未提供登录凭证，优先检查站点根目录、.htaccess 和 Apache 重启状态。

### 8.2 Nginx/PHP-FPM

~~~nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;
    root /var/www/mytotal/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~* ^/storage/.*\.(php|phtml|phar)$ {
        deny all;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param HTTP_AUTHORIZATION $http_authorization;
        fastcgi_pass 127.0.0.1:9000;
    }

    location ~ /\. {
        deny all;
    }
}
~~~

上线前确认 HTTPS、证书续期、HSTS、请求体大小、超时和访问日志策略；不要把项目根目录、.env、vendor/、config/ 或 runtime/ 暴露为静态资源。

## 9. 发布验收

### 9.1 公共接口

~~~bash
curl -i https://api.example.com/api/sample/v1/health
curl -i https://api.example.com/api/sample/v1/app/bootstrap
~~~

预期：HTTP 200、JSON code=0，并返回 request_id。bootstrap 不得包含 AppSecret、数据库地址或内部权限信息。

### 9.2 登录和业务接口

使用真实小程序 wx.login 的 code 调用：

~~~text
POST /api/sample/v1/auth/wechat-login
{
  "appid": "wx-your-appid",
  "code": "wx.login 返回的 code"
}
~~~

保存响应中的 access_token 和 refresh_token 后，携带：

~~~text
Authorization: Bearer <access_token>
~~~

至少验收以下接口：

~~~text
GET  /api/sample/v1/users/me
GET  /api/sample/v1/foods
GET  /api/sample/v1/food-pool
POST /api/sample/v1/food-draws
GET  /api/sample/v1/food-book
GET  /api/sample/v1/food-book/{food_id}
GET  /api/sample/v1/food-stats
POST /api/sample/v1/feedback
~~~

验收重点：

- 无 Token 的业务接口返回 40100 或 40101；
- 不同小程序和不同用户之间不能读取或修改数据；
- 空奖池返回 42201；抽取重复幂等键不重复计数；
- 图鉴详情返回 origin、steps、tip、draw_count、first_drawn_at、last_drawn_at；
- 每次请求可用 request_id 在对应小程序日志中定位。

### 9.3 前端联调顺序

1. 配置 API_BASE_URL=https://api.example.com 和 programKey=sample。
2. 调用 /health、/app/bootstrap。
3. 调用微信登录并保存令牌。
4. 并行加载 /users/me、/food-pool、/food-stats。
5. 根据服务端返回的美食执行抽取、历史、图鉴和反馈流程。
6. 401 时只允许统一请求层刷新令牌；刷新成功后用新 Token 重放原请求。

## 10. 日常发布、升级和回滚

### 10.1 标准发布顺序

~~~bash
git fetch origin
git checkout main
git pull --ff-only origin main
composer install --no-dev --optimize-autoloader
php think clear
php database/migrate.php status
php database/migrate.php up
~~~

若本次包含新的美食内容，再执行对应 seed；若只是代码发布，不要重复执行会改变业务数据的脚本。发布完成后重新执行健康检查和关键业务接口验收。

### 10.2 数据库变更规则

- 已执行的 migration 不修改；新增结构必须新增时间序列 migration。
- 发布前做数据库备份，并在预发验证空库、升级库和回滚库。
- down 仅用于明确批准的回滚演练或发布回退，不用于清理生产数据。
- 内容调整优先使用独立 seed/后台操作，不把业务数据写进结构迁移。

### 10.3 回滚原则

代码回滚与数据库回滚分开评估。若新代码兼容旧表结构，优先回滚代码并保留数据库变更；只有确认数据可恢复、接口兼容和备份有效时，才执行对应 down migration。回滚后重新检查 /health、登录、奖池和图鉴接口。

## 11. 常见问题

| 现象 | 排查顺序 |
| --- | --- |
| Controller not exists: app\\controller\\Index | 检查站点是否进入当前版本；确认 route/app.php 已加载公共根路由，站点根目录指向 public/ |
| 请求带 Authorization 但返回 40100 | 检查 Apache .htaccess、Nginx HTTP_AUTHORIZATION、PHP-FPM/Apache 重启；返回 40101 说明请求头已到达 PHP |
| 迁移失败：There is no active transaction | 确认使用当前 database/migrate.php；该迁移器不对 MySQL DDL 包事务，检查失败语句和实际表结构后重试 |
| not support: redis | 检查 Redis 服务、.env、predis/predis 和 PHP 扩展；不要直接改回 file 掩盖线上依赖问题 |
| 微信登录返回 50000 | 检查 APP_KEY、secret_ciphertext，重新运行 set_mini_program_secret.php |
| 微信登录返回 50300 | 检查 AppID/AppSecret、服务器出网、DNS、证书和微信接口状态 |
| 图片上传后无法访问 | 检查 public/storage/images 权限、静态 URL 前缀和 Web 服务器脚本执行限制 |
| 日志没有写入 | 检查 runtime/program_logs 权限、磁盘空间和 config/log.php 的 program.enabled |
| /food-book/10 被列表接口处理 | 确认 config/route.php 开启 route_complete_match=true，并清理缓存 |

## 12. 上线检查清单

- [ ] 站点根目录为 public/，HTTPS 和小程序合法域名已生效。
- [ ] APP_DEBUG=false，.env 不在版本库，密钥由部署系统管理。
- [ ] Composer 依赖安装完成，composer check-platform-reqs 无阻断项。
- [ ] MySQL、Redis 可用，迁移状态完整，数据库已备份。
- [ ] sample 在配置白名单和 sys_mini_program 中均已启用。
- [ ] AppSecret 已通过命令加密写入，数据库中没有明文密钥。
- [ ] database/food_module.sql 已按目标小程序导入，启用美食数量正确。
- [ ] 图片目录可写且禁止执行脚本，日志目录可写且不对公网开放。
- [ ] 健康检查、微信登录、奖池、抽取、图鉴、统计和反馈验收通过。
- [ ] 日志轮转、备份、监控、磁盘告警和回滚负责人已明确。
