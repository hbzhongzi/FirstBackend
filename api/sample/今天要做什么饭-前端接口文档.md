# “今天要做什么饭”小程序前端接口文档

> 面向微信小程序前端开发者的调用契约。本文只描述客户端需要使用的接口和状态管理方式；数据库字段、迁移和后端分层请参考同目录的后端落地说明与 SQL 文档。

## 1. 基础约定

### 1.1 请求地址

```text
{API_BASE_URL}/api/{programKey}/v1
```

- `API_BASE_URL` 由环境配置提供，例如 `https://api.example.com`。
- 当前示例小程序的 `programKey` 为 `sample`。
- 当前完整前缀示例：`https://api.example.com/api/sample/v1`。
- 不要把 `appid`、`program_id` 或 `user_id` 拼接到业务请求中切换小程序；项目身份由 URL 路由确定。

### 1.2 请求头

登录后接口统一携带：

```text
Authorization: Bearer <access_token>
X-Request-Id: <可选，建议使用 UUID>
Content-Type: application/json
```

上传图片时将 `Content-Type` 交给小程序运行时设置为 `multipart/form-data`，仍需携带 `Authorization`。旧客户端的 `token` 头仅用于过渡兼容，新代码不要继续使用。

### 1.3 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": 1793351360,
  "request_id": "5f0c2f9b-7d70-4fc9-9e7a-6c6cbf9fb8b1"
}
```

- `code=0` 表示业务成功。
- `data` 的结构由接口决定；无数据时为 `null`。
- `request_id` 用于向后端反馈问题，前端日志应保存它，不要保存 Token。
- 失败时同时检查 HTTP 状态码和业务 `code`，不要只判断 HTTP 200。

常用错误码：

| HTTP | code | 前端处理 |
| ---: | ---: | --- |
| 400 | `40000` | 请求格式错误，提示并修正参数 |
| 401 | `40100` / `40101` | 清理本地登录态，重新登录 |
| 404 | `40400` | 资源不存在或已停用 |
| 404 | `40401` | 小程序未注册或已停用 |
| 422 | `42200` | 参数校验失败，展示 `message` |
| 422 | `42201` | 奖池为空，要求至少选择一项美食 |
| 429 | `42900` | 延迟后重试，不要自动快速循环请求 |
| 500 | `50000` | 展示通用错误，并记录 `request_id` |

## 2. 登录与启动流程

推荐启动顺序：

1. 读取前端环境中的 `API_BASE_URL` 和 `programKey`。
2. 调用 `GET /app/bootstrap` 获取版本和上传限制。
3. 使用 `wx.login` 获取临时 `code`。
4. 调用 `POST /auth/wechat-login`，保存返回的 `access_token` 和 `refresh_token`（如果服务端返回）。
5. 登录成功后调用 `GET /users/me`、`GET /food-pool` 和 `GET /food-stats` 初始化页面。

### 2.1 `GET /health`

无需登录，用于开发联调和部署检查。

```json
{
  "status": "ok",
  "service": "wechat-mini-program-api",
  "program_key": "sample"
}
```

### 2.2 `GET /app/bootstrap`

无需登录。返回当前小程序公开配置，不会返回 AppSecret、数据库地址等服务端信息。

```json
{
  "program_key": "sample",
  "name": "示例小程序",
  "api_version": "v1",
  "upload": {
    "image_max_bytes": 10485760,
    "allowed_extensions": ["jpg", "jpeg", "png", "webp"]
  },
  "features": {}
}
```

### 2.3 `POST /auth/wechat-login`

无需登录。`code` 来自本次 `wx.login`，不能缓存后重复使用。

请求体：

```json
{
  "appid": "wx-your-appid",
  "code": "微信临时登录 code",
  "device_id": "可选设备标识",
  "nickname": "可选昵称",
  "avatar_url": "可选头像地址"
}
```

`appid` 必填，服务端按它查询数据库中的启用小程序注册记录，并校验它与当前接口 URL 的 `programKey` 一致。前端可以提交公开 AppID，但不能提交或覆盖 `program_id`、AppSecret。

成功数据：

```json
{
  "user": {
    "id": 10001,
    "nickname": "微信用户",
    "avatar_url": null,
    "is_new_user": true,
    "is_phone_bound": false,
    "created_at": "2026-10-30 12:00:00"
  },
  "token": {
    "access_token": "服务端签发的访问令牌",
    "token_type": "Bearer",
    "expires_in": 7200,
    "refresh_token": "服务端返回时保存"
  }
}
```

前端只保存令牌和必要的用户展示信息；不要解析 Token 内容，也不要把 openid、session_key 当作前端身份凭证。

### 2.4 `POST /auth/refresh`

无需携带已过期的 access token，请求体传 refresh token：

```json
{ "refresh_token": "refresh-token" }
```

成功后替换本地旧令牌。刷新失败时清理登录态并重新走微信登录。

### 2.5 `POST /auth/logout`

需要登录。成功后服务端撤销当前会话，前端同时删除本地令牌。

## 3. 公共用户与文件接口

### 3.1 `GET /users/me`

需要登录，返回当前小程序下的用户资料：

```json
{
  "id": 10001,
  "nickname": "微信用户",
  "avatar_url": null,
  "is_new_user": false,
  "is_phone_bound": false,
  "created_at": "2026-10-30 12:00:00"
}
```

### 3.2 `PATCH /users/me`

只允许修改 `nickname`、`avatar_url`：

```json
{ "nickname": "新的昵称", "avatar_url": "https://example.com/avatar.png" }
```

不要提交 `id`、`program_id`、`openid`、`status` 等系统字段。

### 3.3 `POST /files/images`

需要登录，使用 `multipart/form-data`，字段名必须为 `file`。当前支持 JPEG、PNG、WebP，默认最大 10 MiB。

成功数据：

```json
{
  "id": 90001,
  "type": "image",
  "original_name": "avatar.png",
  "size_bytes": 2048,
  "mime_type": "image/png",
  "url": null,
  "security_status": "pending",
  "created_at": "2026-10-30 12:00:00"
}
```

`security_status=pending` 时 `url` 可能为 `null`，前端不能把它当作审核通过。图片会由服务端按小程序和年月固定存储，前端只使用接口返回的 `url`。

### 3.4 文件查询与删除

- `GET /files/{file_id}`：查询当前小程序下的文件元数据。
- `DELETE /files/{file_id}`：只能删除当前用户上传的文件，成功 `data=null`。

## 4. 美食内容接口

以下接口均需要登录。

### 4.1 `GET /foods`

获取当前小程序启用的美食列表。查询参数：

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | ---: | --- |
| `page` | integer | 1 | 页码，小于 1 时使用 1 |
| `page_size` | integer | 50 | 每页 1-100 |

成功数据：

```json
{
  "items": [
    {
      "id": 1,
      "name": "火锅",
      "emoji": "🍲",
      "image_url": null,
      "description": "约上三五好友，热气腾腾最热闹。",
      "enabled": true
    }
  ],
  "total": 12,
  "page": 1,
  "page_size": 50
}
```

`enabled` 是当前用户奖池状态，不是平台内容启用状态。

### 4.2 `GET /foods/{food_id}`

获取启用美食详情：

```json
{
  "id": 1,
  "name": "火锅",
  "emoji": "🍲",
  "image_url": null,
  "description": "约上三五好友，热气腾腾最热闹。",
  "enabled": false,
  "origin": "起源小知识",
  "steps": ["准备食材", "烧开汤底", "依次涮煮"],
  "tip": "科普小贴士"
}
```

当前实现中详情接口的 `enabled` 固定为 `false`，详情页如需显示“已加入奖池”，请使用列表或奖池接口中的同名字段，不要以详情接口该字段作为判断依据。

## 5. 奖池接口

### 5.1 `GET /food-pool`

首次读取时，服务端会为新用户初始化全部启用美食。

```json
{
  "enabled_food_ids": [1, 2, 3],
  "enabled_count": 3,
  "total_count": 12,
  "items": [
    { "id": 1, "name": "火锅", "emoji": "🍲", "image_url": null, "description": "...", "enabled": true }
  ]
}
```

### 5.2 `PUT /food-pool`

覆盖保存当前用户奖池，请求体：

```json
{ "food_ids": [1, 2, 3] }
```

`food_ids` 必须是非空数组，只能包含当前小程序的启用美食。保存成功直接返回完整奖池结构。前端“全选”和“重置”只负责生成数组，最终以服务端响应更新页面。

## 6. 抽取接口

### 6.1 `POST /food-draws`

转盘和盲盒共用接口，服务端负责随机选择和记录结果。

请求体：

```json
{
  "mode": "wheel",
  "idempotency_key": "draw-20261030-0001"
}
```

`mode` 只能是 `wheel` 或 `box`。`idempotency_key` 必填，长度不超过 128；建议由前端为每次用户操作生成 UUID。网络重试必须复用同一个 key，不能重新生成。

成功数据：

```json
{
  "draw_id": 10001,
  "mode": "wheel",
  "food": {
    "id": 1,
    "name": "火锅",
    "emoji": "🍲",
    "image_url": null,
    "description": "约上三五好友，热气腾腾最热闹。",
    "enabled": true
  },
  "draw_count": 8,
  "book_count": 4,
  "food_draw_count": 3,
  "drawn_at": "2026-10-30 18:30:00"
}
```

前端动画只能展示服务端返回的 `food`，不能提交 `food_id` 或使用本地随机结果覆盖服务端结果。奖池为空时处理 `42201`。

### 6.2 `GET /food-draws`

查询当前用户抽取历史，按最新记录倒序。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | ---: | --- |
| `page` | integer | 1 | 页码 |
| `page_size` | integer | 20 | 每页 1-100 |
| `mode` | string | 空 | `wheel` 或 `box` |

每项结构与抽取接口相同，包含 `draw_id`、`mode`、`food`、统计字段和 `drawn_at`。

## 7. 图鉴与统计

### 7.1 `GET /food-book`

查询已抽到的美食，按最近抽到时间倒序：

```json
{
  "items": [
    {
      "food_id": 1,
      "name": "火锅",
      "emoji": "🍲",
      "draw_count": 3,
      "first_drawn_at": "2026-10-01 12:00:00",
      "last_drawn_at": "2026-10-30 18:30:00",
      "status": "active"
    }
  ],
  "collected_count": 4,
  "total_food_count": 12,
  "total": 4,
  "page": 1,
  "page_size": 20
}
```

### 7.2 `GET /food-book/{food_id}`

只允许查看当前用户已经收录的美食，并返回详情字段 `origin`、`steps`、`tip` 以及 `draw_count`、`first_drawn_at`、`last_drawn_at`。未收录返回 `40400`。

成功数据示例：

```json
{
  "id": 10,
  "name": "盖浇饭",
  "emoji": "🍚",
  "image_url": null,
  "description": "一锅出，最快解决一餐。",
  "enabled": false,
  "origin": "中式快餐经典，米饭浇上现炒菜肴，便捷管饱。",
  "steps": [
    "煮饭：米饭蒸熟备用",
    "炒菜或卤：选宫保鸡丁、番茄蛋或红烧类",
    "勾芡收汁：让汤汁裹住食材",
    "浇饭：热菜连汁铺在米饭上"
  ],
  "tip": "一餐同时含主食与菜，注意蔬菜比例偏低，建议搭配一份清炒时蔬更均衡。",
  "draw_count": 1,
  "first_drawn_at": "2026-10-31 10:08:19",
  "last_drawn_at": "2026-10-31 10:08:19"
}
```

`steps` 始终为字符串数组；弹层分别将 `origin`、`steps`、`tip` 映射为“起源小知识”“家常做法”“科普小贴士”。

### 7.3 `GET /food-stats`

个人中心统计：

```json
{
  "draw_count": 8,
  "book_count": 4,
  "total_food_count": 12,
  "last_drawn_at": "2026-10-30 18:30:00"
}
```

当前 `GET /users/me` 只返回用户资料，不包含业务统计；个人中心需同时调用 `users/me` 和 `food-stats`。

## 8. 反馈接口

### `POST /feedback`

请求体：

```json
{
  "type": "feature",
  "content": "希望增加晚餐推荐筛选",
  "food_name": null,
  "contact": null,
  "idempotency_key": "feedback-20261030-0001"
}
```

字段约束：

| 字段 | 必填 | 取值/长度 |
| --- | --- | --- |
| `type` | 是 | `feature`、`bug`、`food_recommendation`、`other` |
| `content` | 是 | 1-2000 个字符 |
| `food_name` | 否 | 最长 64 个字符 |
| `contact` | 否 | 最长 128 个字符 |
| `idempotency_key` | 否 | 最长 128 个字符，重试时复用 |

成功响应：

```json
{
  "feedback_id": 30001,
  "status": "pending",
  "created_at": "2026-10-30 18:35:00"
}
```

当前代码已完成类型、长度和幂等校验；生产环境的敏感词服务和限流仍需按部署方案接入。

## 9. 页面与接口映射

| 前端页面/组件 | 首次进入 | 用户操作 |
| --- | --- | --- |
| 启动页 | `/health`、`/app/bootstrap` | 微信登录、令牌刷新 |
| 首页转盘/盲盒 | `/food-pool`、`/foods` | `POST /food-draws` |
| 奖池设置 | `/food-pool` | `PUT /food-pool` |
| 抽取历史 | `GET /food-draws` | 分页加载 |
| 美食图鉴 | `GET /food-book` | `GET /food-book/{food_id}` |
| 个人中心 | `/users/me`、`/food-stats` | `PATCH /users/me` |
| 建议反馈 | 无 | `POST /feedback` |
| 头像/图片上传 | 无 | `POST /files/images` |

## 10. 前端请求封装建议

```js
const API_ROOT = `${API_BASE_URL}/api/${programKey}/v1`;

async function request(path, options = {}) {
  const token = wx.getStorageSync('access_token');
  const header = {
    'Content-Type': 'application/json',
    ...(options.header || {})
  };
  if (token) header.Authorization = `Bearer ${token}`;

  const response = await wx.request({
    url: `${API_ROOT}${path}`,
    ...options,
    header
  });
  const body = response.data || {};
  if (body.code === 0) return body.data;
  if (body.code === 40100 || body.code === 40101) {
    wx.removeStorageSync('access_token');
    wx.removeStorageSync('refresh_token');
  }
  throw new Error(body.message || '请求失败');
}
```

真实项目应在请求层统一处理刷新令牌、重复请求队列、网络超时和错误提示。刷新成功后必须同时覆盖本地 `access_token`、`refresh_token`，再使用新 access token 重放原请求；登录态失效时不要在每个页面各自实现一套逻辑。

PHPStudy/Apache 联调时，如果小程序 Network 面板能看到 `Authorization: Bearer ...`，但接口仍返回 `40100/未提供登录凭证`，应先重启 Apache 并检查站点根目录是否为 `public/`。项目已在 `public/.htaccess` 转发该请求头，服务端也兼容 `HTTP_AUTHORIZATION` 和 `REDIRECT_HTTP_AUTHORIZATION`；若返回 `40101`，表示请求头已到达 PHP，只需检查令牌是否过期或是否使用了刷新前的旧令牌。

## 11. 原型状态迁移规则

原型 HTML 的 `FOODS`、`history`、`book`、`drawCount` 和 `localStorage` 只用于演示。正式小程序接入后：

- 奖池以 `GET/PUT /food-pool` 为唯一事实来源。
- 抽取结果以 `POST /food-draws` 返回值为准。
- 历史和图鉴从服务端分页接口读取。
- 页面缓存只能用于启动展示和离线兜底，不能覆盖服务端成功响应。
- 前端不要提交 `program_id`、`user_id`、`food_id`（作为抽取结果）、`draw_count` 或 `book_count`。

## 12. 联调验收清单

- [ ] 未登录访问业务接口返回 `40100` 或 `40101`。
- [ ] 新用户首次读取奖池自动拥有全部启用美食。
- [ ] 奖池不能为空，停用或跨小程序美食 ID 会被拒绝。
- [ ] 转盘和盲盒都使用服务端返回结果，重复 key 不重复计数。
- [ ] 历史、图鉴和统计只返回当前用户、当前小程序数据。
- [ ] 反馈类型和长度校验符合文档，重试复用幂等键。
- [ ] 所有异常上报都带 `request_id`，前端日志不记录 Token。
